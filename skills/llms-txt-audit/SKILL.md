# llms-txt-audit

Audit any website for `llms.txt` — the emerging standard for LLM-friendly site summaries. Detect missing, stale, or malformed files. Generate a compliant `llms.txt` from crawled content when needed.

**Attribution:** Method adapted from [romankurnovskii.com/llms-txt-guide](https://romankurnovskii.com/llms-txt-guide)

---

## When to Use This Skill

- **Site owners** preparing for AI-era discoverability — ensure your site has a valid `llms.txt`
- **SEO/AEO practitioners** auditing client sites for LLM-readiness
- **Developers** integrating `llms.txt` generation into CI/CD pipelines
- **Researchers** studying AI crawler behavior and site indexing patterns

---

## Prerequisites

- Target website must be publicly accessible (or provide auth credentials)
- Python 3.10+ with `httpx`, `beautifulsoup4`, `lxml`, `markdownify`
- Optional: `get-llms-txt` CLI installed (`pip install get-llms-txt`)

---

## Inputs

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `url` | string | Yes | Root URL of the site to audit (e.g., `https://example.com`) |
| `max_pages` | integer | No | Maximum pages to crawl for content extraction (default: 50) |
| `check_freshness_days` | integer | No | Flag `llms.txt` as stale if older than this many days (default: 30) |
| `generate_if_missing` | boolean | No | Auto-generate `llms.txt` if missing or stale (default: false) |
| `output_path` | string | No | Local path to write generated `llms.txt` (default: `./llms.txt`) |

---

## Procedure

### 1. Discover `llms.txt`

```bash
# Check standard locations
curl -sI "$URL/llms.txt"        # Root
curl -sI "$URL/.well-known/llms.txt"  # Well-known path
```

- Follow redirects (301/302)
- Record HTTP status, `Last-Modified`, `Content-Length`, `Content-Type`

### 2. Validate `llms.txt` Structure

If found, parse and verify:

```
# Required: H1 title (site name)
# Required: One-line description (≤ 200 chars)
# Required: At least one link section with entries

## Section Name
- [Link Title](https://example.com/page) — One-line benefit/description
```

**Validation checks:**
- [ ] File exists and returns 200 OK
- [ ] Contains H1 title (first non-empty line starting with `# `)
- [ ] Contains description paragraph after H1
- [ ] Contains at least one `##` section with `- [Title](URL) — description` entries
- [ ] All URLs are absolute and reachable (HEAD 200)
- [ ] `Last-Modified` ≤ `check_freshness_days` ago (if header present)
- [ ] File size > 100 bytes (not empty placeholder)

### 3. Crawl Site for Content (if generating or validating coverage)

```
BFS crawl from root URL:
- Respect robots.txt
- Follow only same-domain links
- Skip: /api/, /admin/, /login/, /cart/, /checkout/, *.pdf, *.zip, *.exe
- Extract: <title>, <meta description>, <h1>, main content text
- Limit: max_pages
```

For each page, compute:
- **Title** (from `<title>` or first `<h1>`)
- **Description** (from `<meta name="description">` or first 160 chars of content)
- **URL** (canonical)
- **Priority** (heuristic: homepage > docs > blog > landing > other)

### 4. Generate `llms.txt`

If missing, stale, or `generate_if_missing=true`:

```
# Site Name
One-sentence description of what the site does for visitors.

## Core Pages
- [Home](https://example.com) — What this site offers in one line
- [Documentation](https://example.com/docs) — Technical reference and guides
- [API Reference](https://example.com/api) — Endpoint specifications

## Guides & Tutorials
- [Getting Started](https://example.com/guides/getting-started) — First steps for new users
- [Authentication](https://example.com/guides/auth) — How to authenticate API calls

## Blog / Updates
- [Latest Release](https://example.com/blog/v2-release) — What's new in v2
- [Changelog](https://example.com/changelog) — Full version history
```

**Generation rules:**
- Group links under logical `##` sections (Core, Guides, API, Blog, etc.)
- Each entry: `- [Title](URL) — one-line benefit for the reader`
- Sort by priority within each section
- Cap at ~50 total links (LLM context window friendly)
- Include attribution comment: `<!-- Generated by llms-txt-audit skill — romankurnovskii.com/llms-txt-guide -->`

### 5. Output Report

Return structured result:

```json
{
  "url": "https://example.com",
  "llms_txt": {
    "found": true,
    "location": "https://example.com/llms.txt",
    "status": 200,
    "last_modified": "2026-09-15T10:30:00Z",
    "size_bytes": 2847,
    "valid": true,
    "fresh": true,
    "validation": {
      "has_h1": true,
      "has_description": true,
      "has_sections": true,
      "links_reachable": 47,
      "links_broken": 0
    }
  },
  "crawl": {
    "pages_crawled": 42,
    "candidate_links": 89,
    "selected_links": 47
  },
  "generated": false,
  "output_path": null
}
```

If generated:

```json
{
  "url": "https://example.com",
  "llms_txt": { "found": false },
  "crawl": { "pages_crawled": 42, "candidate_links": 89, "selected_links": 47 },
  "generated": true,
  "output_path": "./llms.txt"
}
```
